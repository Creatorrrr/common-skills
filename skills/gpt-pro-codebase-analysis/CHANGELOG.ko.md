# 변경 사항 — v2.0.0

작성일: 2026-09-05. 대상: 첨부된 `gpt-pro-codebase-analysis.zip`.

## 저장소 반영 시 추가 검토 및 보완

2026-09-05에 개선판 ZIP과 참조 대화를 현재 저장소와 대조했습니다. 첨부본의
80개 테스트를 재실행한 뒤, 읽기 권한 오류 파일을 바이너리로 분류해 `full`
준비를 성공 처리하는 누락 경로를 수정하고 회귀 테스트를 추가했습니다.
로컬 전용 준비를 제외하던 스킬 설명과 분석 계약/실행 제약의 구분도 정리했습니다.

최종 단위 테스트 **81개**, 공식 OpenAI SDK 3.8.0의 HTTP 모의 전송 테스트
**3개**가 통과했습니다. SDK 검증에는 Sol/Astra 요청, 검색 파일 업로드 형식과
만료, 수집, 삭제, HTTP 오류 후 정리가 포함됩니다. 정적 검사·문법·스킬 형식도
통과했습니다. 실제 API·브라우저·모델 품질 검증은 수행하지 않았습니다.
상세한 적용 차이와 원본/현재 검증의 구분은 [검증 기록](validation/VALIDATION.md)에 있습니다.

## 변경 목적

기존의 근거 중심 분석, API/Web 분리, 외부 의견에 대한 로컬 검증은 유지합니다. 지시문을 강화하는 데 그치지 않고 실제 입력 준비·전송·결과 상태·리소스 정리에서 같은 계약이 지켜지도록 변경했습니다. 기본 모델은 임의로 교체하지 않았습니다.

## 지시 설계 변경

사용자 지시, 스킬 기본값, 신뢰된 호스트 지침, 감사 대상 저장소 문서를 구분했습니다. 이미 받은 유효한 승인과 알려진 목표·형식을 다시 묻지 않도록 했습니다. 로컬 준비와 외부 전송의 권한 경계를 분리했고, 중단이 필요한 경우 실제 적용되는 규칙과 미결정 사항을 설명하도록 했습니다.

목표·허용 경로·비목표·제약·언어·형식·깊이·완료 기준을 하나의 JSON 분석 계약으로 만들었습니다. API와 Web에 같은 계약이 전달되며, 명시적인 사용자 형식은 기본 보고서 섹션보다 우선합니다. 과거의 고정된 1~3개 흐름 추적 대신 목표·위험·불확실성에 따른 검증과 종료 조건을 사용합니다.

README·주석·업로드된 `AGENTS.md`에 있는 명령문은 모델에 대한 새 지시가 아니라 감사 데이터임을 명시했습니다. 이것은 방어 지침이지 모든 프롬프트 주입을 막았다는 실험 결과는 아닙니다.

## 실행 구조 변경

`scripts/context_integrity.py`는 스냅샷 파일·준비 산출물 해시, full/focused 선택 목록, 이전/현재 경로 이동, 승인 결합을 담당합니다. 승인 기록은 run ID, snapshot ID, 선택 집합, 분석 계약, 제외 목록, 전송 경로 및 실행 조건을 묶습니다. `authorize_analysis.py`는 실제로 받은 승인을 기록할 뿐 사용자를 대신해 동의를 만들지 않습니다.

Direct 모드는 첨부 Files 방식에서 정규화된 `input_text` 방식으로 변경했습니다. 계산에 사용한 입력/지침/추론 설정이 실제 생성 요청에도 사용됩니다. File Search는 원본 확장자 그대로 올리지 않고 원래 경로·해시·줄/열·분할 정보를 포함한 UTF-8 `.txt`로 변환합니다. 긴 한 줄, CRLF, 한국어, UTF-16 입력, 빈 파일을 테스트했습니다. 원본 바이트는 스냅샷에 보존합니다.

수집 상태를 모든 파일에 대해 확인하며, 하나라도 실패하면 분석을 제출하지 않습니다. 재사용하는 Vector Store는 영수증뿐 아니라 원격 메타데이터·전체 멤버십·수집 상태·파일 내용 해시까지 검사합니다. 외부 소유 리소스는 새 실행의 삭제 대상으로 등록하지 않습니다.

Web 패키지도 스냅샷에서만 구성합니다. 누락/추가/중복 ZIP 멤버와 최종 크기를 검사하고, 제외 파일의 상세 이름·민감정보 검사 세부사항은 외부 메타데이터에서 제외했습니다. 도구 자체는 브라우저를 열거나 업로드하지 않습니다. 자동화용 로컬 복사본은 별도 명시 승인이 있어야 만듭니다.

## 실패·정리·완료 상태

새 실행은 기존 결과를 `attempts/`로 보존한 뒤 현재 상태를 초기화합니다. `.run.lock`으로 동일 출력 폴더의 동시 실행을 막습니다. 응답 실패·빈 응답·입력 검증 실패·통신 예외·키보드 중단을 성공으로 표시하지 않으며, SDK 자동 재시도는 끕니다.

새 Files와 Vector Store에는 만료를 지정하고 기본적으로 종료 시 삭제를 시도합니다. 명시적으로 승인된 성공 실행만 보관할 수 있습니다. 삭제 확인 실패 시 별도 상태와 종료 코드 2를 반환합니다. 강제 종료·알 수 없는 서버 측 생성 결과까지 완벽히 정리한다는 보장은 하지 않습니다.

`response_completed`와 `analysis_validation`/`local_verification`을 분리했습니다. 제공된 파일, 검색 결과에 나온 파일, 실제로 확인한 파일, 로컬에서 검증한 결론을 같은 것으로 취급하지 않습니다. 후속 응답 연결에는 같은 스냅샷·선택 범위·사용자 계약·모델의 저장된 완료 응답이라는 조건을 추가했습니다.

## 기본값 및 호환성 변경

| 항목 | 이전 → 개선 |
|---|---|
| 기본 모델 | `gpt-5.6-sol` 유지 |
| reasoning-mode | `pro` → 모델별 `auto` (Sol의 실제 전송은 여전히 Pro) |
| reasoning-effort | `high` 유지 |
| verbosity | `high` → `medium` |
| background | 기본 활성화 → 기본 비활성화 |
| response store | 기본 활성화 → 기본 비활성화 |
| 새 Files/Vector Stores | 별도 정리 흐름 부족 → 기본 삭제 + 만료 + 저널 |
| 승인 | 문서 중심 → 실행 조건과 일치하는 로컬 승인 기록 검사 |
| 기존 manifest | 재사용 가능 경로 → v2 스냅샷 재준비 필요 |
| scope | 경로 힌트/일부 확장 → 실제 허용 경로 경계 |
| API 키 로딩 | 기본 `.env` 로딩 → 환경 변수 또는 명시한 신뢰된 파일만 |
| 임의 모델 이름 | 일반 문자열 → 확인된 모델 프로필만 허용 |

Astra를 선택할 때 authorizer와 runner 양쪽에 `--model gpt-6-astra --reasoning-mode auto --reasoning-effort high`를 동일하게 지정합니다. Astra에 Sol용 `reasoning.mode=pro`를 넘기지 않습니다. 이 설정은 공식 문서 기반의 보수적인 검증이며 실제 호출로 검증한 결과는 아닙니다.

## 검증

첨부 개선판 제작 시 오프라인 테스트: **80개 통과**. 기존 16개 테스트의 주요 검사는 유지했고, 그중 기본 CLI 모드 표기 1개만 `auto`로 변경했습니다. 실제 Sol Pro/high 요청값 검사는 그대로 유지합니다. 신규 64개 테스트를 추가했습니다. 저장소 반영 후 추가 검증은 위 절을 참조합니다.

별도 로그, 원본 테스트 결과, 패키징 검사 결과와 미검증 항목은 `validation/`에 있습니다. 실제 모델의 정확도·비용·속도 비교는 수행하지 않았습니다. `evals/scenarios.jsonl`은 이후 실제 모델 평가를 위한 시나리오 자료이며, 이번 테스트 통과 수에 포함하지 않습니다.
