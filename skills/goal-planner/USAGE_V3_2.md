# goal-planner 3.2 사용법

## 설치 및 기존 작업 유지

ZIP의 `goal-planner/`를 기존에 사용하던 스킬 디렉터리에 배치합니다. 먼저 기존 설치를 별도 위치에 백업하고, 같은 이름의 여러 버전이 동시에 검색되지 않게 합니다. 실제 스킬 경로·호출 방식은 사용 중인 호스트 설정을 따릅니다. 이 파일을 읽었다고 설치되거나 실행되지 않습니다.

기존 GOAL_PLAN, 프로그램/실험 상태, 최선 모델/코드, 수행 중 작업, 자원 사용·예약, 실패/반대 증거와 미해결 목표는 그대로 유지합니다. 이미 시작한 실험은 기존 사전 조건으로 판정하고, 새 단계/기준은 다음 비교에 버전과 이유를 남겨 적용합니다. 과거 결과를 새 기준으로 통과 처리하지 않습니다.

## 자연어 요청 예시

일반 계획:
```text
현재 프로젝트 목적과 진행 상태를 읽고 다음 목표를 작성해줘.
계획 작성만 하고, 프로젝트 변경이나 실행은 하지 마.
```

후보 탐색 계획:
```text
기존 기준선과 실행 환경을 유지하면서 구조 개선을 연구할 계획을 만들어줘.
평가기/필수 제약과 바꿀 수 있는 코드 경계를 먼저 정하고,
소규모 검사→비교 가능한 평가→최종 확인을 구분해줘.
비슷한 후보만 반복하지 않도록 다른 메커니즘과 정체 시 결정을 포함해줘.
기존 모델 프로필과 공유 자원 한도를 유지해줘.
```

기존 연구 계속:
```text
이 스킬의 개선 원칙을 기존 계획에 필요한 만큼 반영해줘.
현재 최선 산출물, 수행 중 실험, 실패 이력, 사용/예약 자원은 보존하고 재초기화하지 마.
이미 승인한 연구 범위에서 다음 결정을 준비해줘.
```

실행까지 요청하려면 실제 작업 공간·기존 실행 흐름과 승인 범위를 함께 사용합니다. 이 스킬을 적용하는 문장만으로 새 도구·백그라운드 실행·하위 모델이 생기지 않습니다. 기존 하위 작업자가 있으면 유지하며 미정인 호출 선택만 필요 시 묻습니다.

## 선택형 실제 도구

[도구 예제](examples/portfolio/README.md)와 [스냅샷](examples/portfolio/snapshot.json)을 참고하세요. `research_portfolio.py`는 입력 선언의 논리적 일관성과 참고 후보를 계산합니다. `build_handoff.py`는 실제 정규 계약을 필요한 것만 넣습니다. 둘 다 API/네트워크/후보 실행/저장소 변경을 하지 않습니다.

```bash
python -B scripts/research_portfolio.py --input examples/portfolio/snapshot.json --stage pilot
python -B scripts/build_handoff.py --goal-file examples/portfolio/goal.md --blocks Core,Experiment,Direction --stats
python -B -m unittest discover -s tests -v
```

한도 초과 시 인계문은 잘리지 않고 오류가 납니다. stdout을 파일로 저장할 때에는 해당 경로에 쓰는 요청/기존 권한이 있어야 합니다. 기존 report_index와 experiment_preflight 도구의 명령과 동작은 바꾸지 않았습니다.

## 검증 의미

유닛/계약/CLI 테스트는 구현을 확인합니다. 실제 모델을 호출하는 행동 평가는 별도이며 이 배포에서 실행하지 않았습니다. 개선된 스킬의 연구 성과·총비용·토큰 감소를 확인하려면 기존 버전과 같은 과제/예산/모델/도구로 비교하고, 직접 결과·근거 완전성·권한 준수까지 평가해야 합니다.
