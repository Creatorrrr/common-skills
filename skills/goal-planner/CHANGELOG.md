- 실행 블록을 Core / Program / Experiment / Direction / Research / Retrieval / Persistence로 구성했습니다. 작은 수정에는 Core만 사용할 수 있으며 적용되는 블록만 계획에 내장합니다.
- 공통 계약의 새 결과 재승인 요구를 **위임된 범위 밖의 변경**으로 한정했습니다. 승인된 후속 이정표를 막던 충돌을 제거했습니다.

- 프로그램 요청에 추가 모드 확인을 요구하지 않고, 필요한 검증·기록만 선택하도록 했습니다. 여섯 단계·여덟 기준은 이정표별 조직화 기본값이지 연구 종료 제한이 아닙니다.
- 모든 실험에 통계·대규모 데이터·독립 평가자를 강제하지 않습니다. 중요한 비교와 채택 주장에 비례하여 검증합니다.
- 사용자 지시와 스킬 기본값의 우선순위를 명확히 하되 상위 지시·실제 권한을 보존합니다. 호출자의 위임 깊이·재하청 금지도 명시합니다.
- 비공개 사고 과정 기록을 요구하지 않고, 관측 가능한 예측·직접 증거·짧은 판단 이유를 남기도록 했습니다.
- 특정 모델이나 API 설정을 하드코딩하지 않았습니다. [가이드 검토](MODEL_GUIDE_REVIEW.md)는 배포 검토용이며 실행마다 읽는 문서가 아닙니다.

## 유지한 기능

결과 우선 완료 기준, 기본 최대 6단계/8개 완료 기준, 위험 비례 검증, 고정 성능 비교 조건, 제한된 수정 반복, 자동 목표 상향 비활성화를 유지했습니다. 분석·보고서 목표에는 불필요한 구현을 만들지 않습니다.

실패·성공 보고서와 연구 자료의 기존 경로·템플릿 필드는 유지했습니다. 관련도 우선 조회, 후보 기본 15건/전문 기본 5건, 보고서 100건·헤더 200 KiB·반복 원문 검색 1초라는 인덱스 검토 조건, 원문 기준 및 연구/실행 보고서 분리도 유지했습니다. 다만 도입 조건 충족이 쓰기 권한까지 부여하지는 않습니다.

성공 기록의 자격은 계속 다음 세 가지로 닫혀 있습니다. 모든 최종 기준이 통과한 뒤 중요한 실패를 해결했거나, 기본 접근 실패 후 비자명한 대안을 확보했거나, 코드/문서에서 저렴하게 복원하기 어려운 필수 다단계 재현 절차를 얻은 경우입니다. 부분 완료·차단 상태에는 성공 보고서를 작성하지 않습니다.

## 파일 구조 변경

`SKILL.md`의 상세 지식 운영 규칙을 `references/execution-knowledge.md`로 이동하고 정리했습니다. 공통 인계 규칙은 `references/execution-contract.md`, 계획 골격은 `assets/goal-plan-template.md`에 있습니다. 실행에 필요한 규칙을 참조로만 숨기지 않고 최종 계획에 내장하도록 했습니다.

진입점 `SKILL.md`는 공백 분리 단어 기준 **3,402 → 1,579**로 줄었습니다. 이는 파일 구성 측정이며 토큰 수나 실제 비용 절감 측정이 아닙니다. 상세 기능은 참조 파일에 남아 있고 배포 문서와 테스트도 추가되어 전체 패키지가 같은 비율로 줄었다는 뜻은 아닙니다.

원본 `tests/test_report_index.py`의 13개 테스트는 수정하지 않았습니다. 새 파일 `tests/test_catalog_recovery.py`에 10개 메서드를 추가했고, `tests/test_skill_contracts.py`에 8개 정적 검사를 추가했습니다. 하위 입력 사례를 개별 테스트 수로 중복 계산하지 않았습니다.

macOS 메타데이터(`__MACOSX`, `._*`)와 Python 캐시(`__pycache__`, `.pyc`)는 배포본에서 제외했습니다.

## 코드 수정 상세

```python
# catalog metadata를 읽기 전에 JSON 컨테이너 유형을 확인한다.
if not records or not isinstance(records[0], dict) or "_meta" not in records[0]:
    raise ReportIndexError("Catalog must start with an _meta object record")
```

이 변경으로 카탈로그가 `42`, `null`, `"_meta"`, `["_meta"]` 등으로 시작해도 `query`는 오류를 알리고 현재 원문 보고서를 검색합니다. 검색은 손상된 카탈로그나 보고서를 수정하지 않습니다. `check`는 유효하지 않은 카탈로그에 비정상 종료 코드를 반환하고, 사용자가 승인한 `sync` 후 `check`로 정상 상태를 확인할 수 있습니다.

스키마 `1`은 유지하고 generator를 `1.0.1`로 올렸습니다. 기존 카탈로그는 버전 메타데이터 차이로 stale 판정될 수 있습니다. 이때 원문 검색을 계속 사용하며 승인된 시점에 재생성합니다.

## 마이그레이션 주의

스킬 폴더 전체를 교체하되 프로젝트의 과거 보고서나 연구 자료는 보존합니다. 기존 `GOAL_PLAN.md`와 복사해 둔 실행 프롬프트는 자동 변환되지 않으므로 재검토가 필요합니다. 지식 기록을 계속 자동화하려는 워크플로에는 `persist`와 기록 허용 경로를 명시합니다. 기록·초기화·실행 승인을 혼합하지 않습니다.

선택적 서브에이전트 사용은 유지 가능한 실행 계획 옵션일 뿐 이 스킬의 필수 의존성이 아닙니다. API 모델 ID, reasoning 설정, 비동기 도구 구현, 개인용 하위 모델 호출 스킬은 추가하지 않았습니다.
