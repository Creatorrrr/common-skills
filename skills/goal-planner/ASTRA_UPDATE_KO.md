# goal-planner 3.2.1 — GPT-6 Astra 기준 재검토

## 확인 결과

3.2.0의 MODEL_GUIDE_REVIEW.md는 GPT-5.6 기준이었다. 당시 일반 규칙 중 상당수는 Astra의 안내와도 맞지만, Astra 전용 검토가 된 것으로 표현할 수 없다. 이번에는 공식 안내의 Using GPT-6 Astra 절과 모델 페이지를 확인했다. 쿼리 URL의 직접 열기 제한과 공식 검색 본문 확인 경로는 [검토 기록](MODEL_GUIDE_REVIEW.md)에 남겼다.

## 변경

실제 SKILL과 인계되는 Core에 일반 표현의 행동 요청 처리, 비본질적 빈칸으로 중단하지 않기, 정확한 skill 조항 설명, 독립 작업의 조건부 분담, 영향에 맞는 검증, 메시지 가독성, 진행 중 요구 변경을 반영했다. 기존 우선순위와 사용자 권한, 목표·실험·증거의 구분을 유지했다.

모델/SDK/API의 설정은 [선택형 Astra 안내](references/gpt-6-astra.md)로 분리했다. 4개 보조 Python 도구 구현은 그대로이고, 새 실행 엔진·API 호출·유료 서비스·자동 모델 변경은 추가하지 않았다. 가이드의 비동기·진행 중 재지정 기능을 스킬 문구만으로 제공한다고 말하지 않는다.

## 적용

기존 스킬 폴더를 검색 경로 밖에 백업한 뒤 ZIP의 goal-planner 폴더로 교체한다. 사용자 수정은 병합한다. 스킬 이름과 기존 사용법은 같으며 새 프로필 스위치는 없다. 현재 선택된 상위/하위 모델·역할·노력 수준·권한·예산은 그대로 둔다.

이미 만들어 둔 GOAL_PLAN.md나 직접 인계문 안의 Core는 설치만으로 갱신되지 않는다. 계속 실행 중인 과제의 원래 기준·판정·best/active 산출물·사용 자원·담당 작업을 보존한 채 관련 계약 문구만 갱신한다. 다른 진행 중 과제를 재시작하지 않는다. 조건부 API 안내는 Astra 호출기를 직접 수정할 때만 읽는다.

## 검증과 한계

[검증 기록](VALIDATION.md)에 이번 로컬 회귀·인계 검사 결과를 기록한다. 기존 166개 검사에 계약 전달·출처 식별·행동 사례 상태 검사 5개를 더한 총 171개 로컬 검사를 실제 실행해 모두 통과했다. 이 검사는 모델이 지침을 실제로 얼마나 잘 따르는지를 측정하지 않는다. 행동 A/B 12개 시나리오는 정의만 작성했고 not_run이다. 전후 연구 성공률·토큰·비용·지연은 not_measured이다.

Core 변경 때문에 인계문은 일부 길어졌다. 이는 토큰 절감 검증이 아니라 필요한 동작 지침의 보완이다. 일반 목표에는 API 문서나 연구 프로그램 규칙이 자동 포함되지 않는다.
