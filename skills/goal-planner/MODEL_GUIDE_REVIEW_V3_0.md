검토일: 2026-09-07 (Asia/Seoul). 대상은 사용자가 지정한 [latest-model 가이드](https://developers.openai.com/api/docs/guides/latest-model)의 당시 표시 내용입니다. 해당 페이지는 변경 가능한 문서이며, 이번에는 GPT-6 Astra의 모델 행동과 프롬프팅 절을 확인했습니다. **스킬의 설계 검토이지 특정 모델의 성능 인증이나 API 설정 검증은 아닙니다.**

## 검토 순서

2.4.0 원본과 기존 검토 결과를 읽고 지속 연구 계약·실험 기록·복구·한글 인덱스를 구현했습니다. 그 수정본을 가이드와 대조하여 공통 승인 문구와 후속 연구 작업 정리의 충돌을 수정했습니다. 이후 템플릿·참조의 일관성을 재검토하고 코드·계약 검사 및 배포 ZIP 검사를 진행했습니다. 결과와 미실행 범위는 [VALIDATION.md](VALIDATION.md)에 분리합니다.

## 가이드 대조표

## 개선 이후 발견하여 바로잡은 사항

### 1. 공통 승인 문구가 승인된 다음 이정표까지 막는 충돌

초기 수정본에서 ‘새로운 결과·권한·비용’이라는 공통 문구를 그대로 두면, Program 블록이 허용한 다음 연구 결과도 새 승인 대상으로 읽힐 수 있었습니다. 이를 **위임된 범위 밖의 새로운 결과**로 좁히고, Program과 Direction에 같은 의미를 반영했습니다. 새로운 외부 비용·권한은 별도로 판단하며, 프로그램 선택 권한이 무제한 권한은 아닙니다.

### 2. 이정표 종료 때 연구 작업을 무조건 정리하는 충돌

진행 중인 연구가 승인된 다음 이정표에 그대로 필요할 수 있습니다. 불필요한 작업은 정리하되 필요한 작업은 담당·근거·남은 공유 자원을 유지하여 다음 이정표로 인계하도록 수정했습니다. 새 목표를 명분으로 중복 실행하거나 자원을 새로 부여하지 않습니다.

### 3. 프로그램 선택과 기록 형식이 또 다른 확인 절차가 되는 위험

`research-program`이라는 정확한 문구나 일률적인 새 수치 예산을 입력받아야만 시작하는 구조로 만들지 않았습니다. 이미 주어진 의도·권한·실제 호스트 한도 안의 제한된 다음 작업을 사용합니다. 미확인 지출을 0으로 처리하지 않고, 실제 새 권한이 필요한 단계만 구분합니다. 기록은 기존 승인 로그를 우선합니다.

### 4. 연구 엄밀성이 작은 수정의 과잉 검증으로 변하는 위험

관련 없는 통계·독립 실행·새 데이터 수집을 의무화하지 않았습니다. 실험 목적과 주장에 필요한 구분 능력을 확보하고, 직접 검증이 부족하면 주장 범위를 제한하도록 했습니다. 여섯 단계·여덟 기준은 이정표별 작성 기본값이지 프로그램 반복 한도가 아닙니다.

### 5. 기록 언어와 기계 처리 형식의 충돌

템플릿의 ‘값은 번역 가능’ 표현은 `Qualification` 같은 열거 값도 임의 번역하도록 읽힐 수 있었습니다. **영어 기계 키·열거 값 유지 / 자유 서술 번역 / 문서화한 한글 상태 별칭만 지원**으로 정리했습니다. Persistence 계약에도 넣어 실행자가 별도 스킬 경로를 읽지 못해도 원칙을 전달받게 했습니다.

### 6. 기본 기록 경로가 프로젝트 사용자 정의를 덮는 위험

실행 계약에 나오는 `docs/...`는 기본값이며 명시적으로 승인한 프로젝트 경로·형식이 우선한다고 블록 내부에 추가했습니다. 스킬 교체가 기존 프로젝트 지식 파일의 이동·덮어쓰기 승인이 되지 않습니다.

## 보조 공식 문서와 적용

[Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices)를 참고하여 비공개 사고 과정의 전개를 요구하지 않고, 관측 가능한 사전 예측·실험 조건·짧은 판단 이유를 남기도록 했습니다. 오래된 특정 모델용 포맷팅 문자열이나 API 메시지 설정을 스킬에 이식하지 않았습니다.

[OpenAI 스킬 문서](https://developers.openai.com/codex/skills/)를 기준으로 로컬 설치 경로와 적용 설명을 확인했습니다. `name`·`description`과 필요한 참조·선택 스크립트를 사용하는 패키지로 유지하며 특정 모델·effort·SDK·개인 보조 스킬에 의존하지 않습니다.

[Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)를 참고하여 코드/정적 회귀 검사와 실제 에이전트 행동 평가를 구분했습니다. 64개 행동 정의는 미실행이며, 테스트 문자열 일치로 실제 연구 성능을 판정하지 않습니다.

## 결론과 남은 검증

정적 대조에서 확인한 승인·종료·기록의 충돌을 수정했고, 프로그램·실험·복구 규칙을 진입점과 실행 인계에 연결했습니다. 검토 결과는 **문서·코드·템플릿 수준에서 적용을 확인한 상태**입니다. 실제 모델이 장기 과제를 안정적으로 진행하는지, 중단·재개 후 예산과 실패를 유지하는지, 성능이나 비용이 개선되는지는 별도 호스트 실행 평가가 필요합니다. 자동 검사 결과는 그 주장을 대신하지 않습니다.
