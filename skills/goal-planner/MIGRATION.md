# 3.0.0 → 3.1.0 적용 안내

동일한 `goal-planner` 이름과 7개 선택 계약, `finite-goal` 기본값, `research-program`의 위임 조건, 보고서 자격, 인덱스 generator `1.1.0`/schema `1`을 유지합니다. 스킬 개선은 다른 대상 프로젝트의 실행·기록 변경을 허가하지 않습니다.

폴더 전체를 검색 경로 밖에 백업하고 교체합니다. 사용자 정의가 있다면 변경 내역을 대조해 병합합니다. 과거 기록은 지우지 않습니다. 이미 복사한 실행 계약은 설치만으로 갱신되지 않으므로 새 스킬로 현재 `GOAL_PLAN.md`를 수정하도록 요청합니다. [사용 예시](USAGE.md)의 마이그레이션 프롬프트를 그대로 사용할 수 있습니다.

현재 계획에서는 원래 기준·실패·예산·권한·최선 산출물을 보존하고, 중요한 실험에 필요한 실제 구성/동작 검증·대조의 의미·진단/확증 분리·증거 우선 검토만 추가합니다. 기존 실험 결과는 소급 사전등록하거나 새 기준으로 성공 처리하지 않습니다. 해석 오류는 원본과 당시 소스 식별자를 남긴 정정으로 처리합니다.

새 `empirical-verification.md`, `verification-template.md`, 선택적 `experiment_preflight.py`와 예제가 포함됩니다. JSON 형식으로 전체 기록을 변환할 필요는 없습니다. 기존 runner의 동등한 점검으로 충분하면 도구를 설치하거나 연결하지 않습니다. 인덱스 구현은 변경하지 않았으며 설치만으로 대상 카탈로그를 재생성하지 않습니다.

기존 테스트 56개와 행동 정의 64개를 유지합니다. 새 코드 테스트와 새 세션 평가 정의는 구분하며, 과거 검증 기록은 [VALIDATION_V3_0.md](VALIDATION_V3_0.md)에 보존합니다. 아래 이전 마이그레이션은 역사 자료입니다.

# 2.4.0 → 3.0.0 적용 안내

3.0.0은 기본 단일 목표를 유지하면서 지속 연구 계약을 추가한 버전입니다. 기존 보고서의 자동 변경, 프로젝트 초기화, 외부 서비스 호출은 없습니다.

## 스킬 폴더

기존 `goal-planner`를 검색 경로 밖에 백업하고 폴더 전체를 교체합니다. 사용자 정의가 있는 경우 파일별 차이를 검토하여 병합합니다. `SKILL.md`와 새 참조·템플릿은 함께 적용해야 합니다. 버전 번호는 [VERSION](VERSION)에서 확인합니다.

## 이미 작성된 계획과 직접 프롬프트

설치만 바꿔도 이미 복사된 실행 지침은 자동 갱신되지 않습니다. 기존 계획의 원래 결과·완료 기준·실험 이력·남은 예산을 보존하고, 새 스킬로 필요한 부분을 검토합니다. 단일 목표는 `finite-goal`로 계속 사용할 수 있습니다.

지속 연구와 다음 목표 선택이 위임된 경우 `research-program` 계약을 추가합니다. 이정표별 기준은 그대로 판정하고 다음 목표의 기준으로 과거 실패를 재분류하지 않습니다. 오래된 ‘다음 목표는 언제나 금지’, ‘새 결과는 무조건 재승인’, ‘프로그램 전체 종료 전 성공 보고 금지’ 식의 포괄 문장이 있다면 위임 범위와 이정표 기준으로 좁힙니다. 위임받지 않은 범위·과금·운영 변경에는 기존 권한 경계를 유지합니다.

7개 계약은 전부 항상 넣는 것이 아닙니다. [execution-contract](references/execution-contract.md)의 적용 조건을 따르고, 완성된 계획에 남은 삽입 표식이 없는지 확인합니다.

## 보고서와 연구 상태

기존 `docs/failed-reports`, `docs/passed-reports`, `docs/researches` 및 사용자 정의 위치를 보존합니다. 새 실험·재개 상태는 승인된 기존 로그나 경로에 최소 기록으로 추가할 수 있습니다. 별도 디렉터리나 데이터베이스를 만들 필요가 없습니다. 과거에 없는 실행 전 예측을 소급해 만든 뒤 사전 등록했다고 표현하지 않습니다.

실험 판정과 보고서 생명주기를 분리합니다. `applied` 연구 노트는 의사결정에 쓰였다는 뜻이며 가설이 참이라는 뜻이 아닙니다. 정식 성공 보고서의 세 가지 자격은 유지하며, 모든 최종 기준 통과 여부는 해당 이정표에 적용합니다.

## 인덱스

기존 스크립트 사본이 있을 때만 승인된 변경으로 generator `1.1.0`을 적용합니다. schema `1`은 그대로이며 예전 카탈로그는 원문 검색으로 복구됩니다. `sync` 후 반드시 `check` 결과를 구분합니다. 정확한 별칭·경고 동작은 [report-index](references/report-index.md)에 있습니다. 영어 키와 열거 값은 유지하고 설명은 한국어로 작성하는 방식이 가장 단순합니다.

## 실제 실행 환경

이 스킬은 모델·reasoning effort·API 키·스케줄러 설정을 바꾸지 않습니다. 실제 지원되는 도구와 승인된 자원 안에서 실행합니다. 중단 뒤 자동 재호출이 없으면 저장된 상태로 다음 세션에서 재개할 수는 있지만, 세션이 끝난 후 계속 연구 중이라고 표시해서는 안 됩니다.
