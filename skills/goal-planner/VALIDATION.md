상위 에이전트가 두 계획의 내용을 직접 읽었고, 합성 프로젝트 3개 파일이 최초 제공 원문과 바이트 단위로 동일함을 확인했습니다. 두 계획 모두 Core·Retrieval 계약 전문을 포함하고 Persistence 블록과 미해결 삽입 표식은 없었습니다. 원문 입력·생성 계획·부모 검토 관측은 [표본 증거](tests/evidence/v2.1-forward-samples.json)에 보존했으며 임시 경로만 정규화했습니다.

이는 **계획 생성 표본 확인**입니다. 실제 프로젝트 개선, 실패 후 장기 계속 수행, 예산 소진 시 실행 종료, Codex/Claude Code 호스트 연동은 시험하지 않았습니다. 기존판과의 A/B 비교나 반복 표본도 없으므로 모델 품질·작업 시간·완료율 개선을 입증한 것으로 해석하지 않습니다. 26개 행동 평가 정의의 전체 실행 결과와도 구분합니다.

## 2.0.0 이전 검증 기록

아래 환경·시간·18개 행동 사례에 관한 설명은 2.0.0 당시의 기록이며 2.1.0의 실행 결과가 아닙니다. 당시 원문 증거를 보존합니다.

검증일: 2026-09-05. 환경: Linux / Python 3.13.5. 테스트는 임시 저장소를 사용했습니다. 사용자의 실제 프로젝트·계정·외부 서비스는 변경하지 않았습니다.

## 실제 재현한 결함과 수정 확인

원본 스크립트에서 첫 카탈로그 레코드가 `42`인 입력을 실행하면 종료 코드 1과 `TypeError: argument of type 'int' is not iterable`이 발생했습니다. [원본 재현 로그](tests/evidence/original-bug.txt)를 포함했습니다.

개선본에서는 숫자·실수·null·불리언·문자열·배열 헤더를 도메인 오류로 처리합니다. 잘못된 metadata/body 유형, 빈 파일, 잘못된 JSON, 잘못된 UTF-8도 검사했습니다. CLI 수준에서 `42`, `null`, `"_meta"`, `["_meta"]`로 시작하는 입력의 원문 검색 복구와 다음 사항을 확인했습니다.

- 검색 결과가 실제 원문 보고서의 해당 사례를 포함합니다.
- 손상된 카탈로그의 내용·수정 시각, 원문 보고서, 디렉터리 항목을 변경하지 않습니다.
- `check`는 잘못된 카탈로그를 성공 처리하지 않습니다.
- 명시적으로 `sync`한 후 `check`가 통과합니다.
- generator 1.0.0 카탈로그는 원문 복구 후 재생성이 가능합니다.

## 검증하지 않은 것

**실제 모델 행동 시나리오 18개는 실행하지 않았습니다.** [시나리오 파일](tests/behavioral-scenarios.json)은 모든 사례를 `not_run`으로 기록합니다. 정적 테스트가 검사하는 것은 파일 구조·참조·표식·알려진 충돌 문구입니다. 실제 에이전트가 부적절한 승인을 묻지 않거나 파일 경계를 준수하는지까지 검증한 결과는 아닙니다.

Codex/Claude Code에 실제 설치하여 실행하는 통합 검사, 모델별 원본/개선본 A/B 비교, 토큰·비용·완료율 측정도 수행하지 않았습니다. Python 3.13.5 이외의 버전에서 별도 실행하지 않았습니다. 템플릿 삽입 검사는 계약 블록을 조립할 수 있는지만 검사하며, 모든 사용자 요청에서 생성될 계획의 의미적 완전성을 보장하지 않습니다.
