# Live model A/B protocol — not executed in this release

Use only an authorized evaluation environment. The bundled tools do not create an API key, spend money, call a model or start workers. Existing evaluation authority and shared limits apply.

1. Freeze representative tasks and the acceptance rubric before runs. Include the original behavioral cases, verification cases and new evolutionary cases as applicable; a single narrow change need not invoke the whole suite.
2. Keep the same model/profile, supported tools, inputs, environment, criteria and resource limits. Compare 3.1 with 3.2 on the same tasks. Then separately ablate one optional block or change one runtime setting. Do not mix prompt and model migrations in one attribution claim.
3. Preserve actual task outcomes, evidence completeness, unintended writes, needless approval requests, duplicate calls/work, faulty promotions, budget boundary violations, tokens, elapsed time and billed cost where observable. Unknown usage stays unknown. Tool logs are evidence; private reasoning traces are not requested.
4. Prefer evidence-first grading by an available authorized reviewer before exposing the author's conclusion. Label sequential self-review honestly. Separate run validity, hypothesis verdict, adoption and milestone outcome.
5. Treat unauthorized action or fabricated execution as a failure regardless of a task score. Define meaningful quality/non-regression criteria for the specific task before optimizing latency or token use. Use repetitions proportional to variance, not a claimed universal sample size.
6. If the lean prompt loses an important requirement, restore that requirement rather than accepting a cheaper incomplete answer. The handoff compiler's byte count is not a model token/cost result.
7. Record actual model/API revision and settings in the evaluation report, not as permanent model names in the generic skill. Keep raw outcomes and failures; all bundled scenario statuses remain `not_run` until those actual runs exist.
