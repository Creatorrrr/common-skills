# 검증 방법 — 3.2.1

패키지 루트에서 실행합니다. 외부 패키지나 API 키가 필요하지 않습니다. 도구는 Python 3.10 이상 문법이며 실제 확인 버전은 [검증 기록](../VALIDATION.md)에 명시합니다.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests -v
```

`-B`와 환경 변수는 부모·자식 프로세스의 캐시 생성을 막습니다. 패키지 청결성 검사 때문에 모두 지정합니다.

정적 검사는 문자열·링크·계약 위치의 회귀를 찾기 위한 것입니다. 문자열이 맞는 것과 에이전트가 지침을 이해·준수하는 것은 다릅니다. 테스트 수, 문서 길이, 스킬 내 성공 선언을 연구 성과의 근거로 사용하지 않습니다.

## 모델 행동 평가: 자동 검사와 별개

[behavioral-scenarios.json](behavioral-scenarios.json)의 64개 사례는 모두 `not_run`입니다. 이전 44개 정의는 보존했고 B45–B64를 추가했습니다. unittest는 정의 파일의 구조만 확인하고 실제 모델·Codex·Claude Code를 호출하지 않습니다.

B45–B64는 지속 연구 계획만 작성, 단일 목표 반복, 승인된 다음 이정표, 유효 반증과 목표 미달, OOM의 두 의미, 불확실한 성능, 최선 산출물 보존, 기회 기반 전환, 오래된 상태에서 재개, 예산 소진, 평가기 변경, 반복 홀드아웃 노출, 기록 권한 부재, 재하청 금지, 구조 전환과 운영 권한, 사전 예측 수정, 병행 자원 예약, 사용자 중지, 진행 중 프로그램의 완료 이정표 보고를 다룹니다.

실행 시 사례별 독립 저장소·모델 세션을 준비하고 모델/effort/도구/권한/예산/원본 파일을 기록합니다. 원본과 개선본에 같은 조건을 사용하며 실행 기록·실제 파일 변화·평가 산출물을 비교합니다. `execution-handoff` 사례는 생성한 계획을 별도 승인된 실행자에게 전달하는 평가로, 계획 작성만 요청한 스킬이 임의로 구현해야 한다는 뜻이 아닙니다.

`must`와 `must_not`은 관측 증거에 따라 판정합니다. 비용 절감을 위해 필수 검증을 생략한 결과나 후보 선택에 사용한 평가만으로 성과를 과장한 결과를 개선으로 인정하지 않습니다. 독립 반복의 변동성, 실패한 실행, 미수행 항목을 모두 보고합니다. 실행 결과는 정의 파일과 분리합니다.

## 새 비교 의미 검증 fixture

[behavioral-verification.json](behavioral-verification.json)에 E01–E16을 추가했습니다. 잘못된 비교군 명칭, 다중 상태 초기화, 초기값 차이, 실패 게이트와 유효한 진단, 결정에 영향을 주지 않는 반복, 보정/예측력 구분, 증거 누락, 누적 예산, 평가기 변경, 작은 수정, 실제 독립성, 보조 경로, 계보 비용, 자기신고 exporter, 자료의 내장 명령, 과거/현재 코드 구분을 다룹니다. 입력 파일 내용까지 포함하며 정의 파일의 `not_run` 값은 유지합니다. 실제 세션 결과는 정의를 덮어쓰지 않고 [검증 기록](../VALIDATION.md)에 별도로 연결합니다.

실제 새 세션의 입력 구성·원본/개선본 비교·원시 출력 보존·관측 기반 판정 절차는 [BEHAVIORAL_EVAL.md](BEHAVIORAL_EVAL.md)에 있습니다. 정의를 정적 검사한 결과를 모델의 판단 성능으로 표시하지 않습니다.
