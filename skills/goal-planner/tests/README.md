# 검증 방법

패키지 루트에서 Python 3.10 이상으로 실행합니다. 외부 Python 패키지나 API 키는 필요하지 않습니다.

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests -v
```

`-B`는 부모 프로세스 옵션이고, `PYTHONDONTWRITEBYTECODE=1`은 기존 테스트에서 생성하는 자식 프로세스에도 캐시 생성을 막습니다. 패키지 청결성 검사 때문에 둘 다 지정하는 편이 안전합니다.

## 자동 검사 범위

| 파일 | 대상 | 의미 |
|---|---|---|
| `test_report_index.py` | 원본의 13개 테스트 유지 | 기존 인덱스 생성·검색·정합성 동작의 회귀 확인 |
| `test_catalog_recovery.py` | 새 10개 테스트 메서드, 유형별 하위 사례 포함 | 잘못된 카탈로그 복구, 비수정 검색, 명시적 재생성 확인 |
| `test_skill_contracts.py` | 8개 정적 검사 | 패키지 구조·참조·계약 삽입·알려진 충돌 문구 확인 |

합계 31개는 unittest 메서드 수입니다. 하위 사례를 독립 테스트처럼 부풀려 세지 않습니다. 정적 문구 검사가 통과해도 모델이 해당 규칙을 올바르게 따랐다는 뜻은 아닙니다.

## 모델 행동 평가: 별도 실행 필요

[behavioral-scenarios.json](behavioral-scenarios.json)의 26개 사례는 평가 정의로 제공되며 상태는 `not_run`입니다. unittest는 파일 구조만 확인합니다. 사용 모델이나 Codex/Claude Code를 자동으로 호출하지 않으며, 미리 성공으로 채운 결과는 없습니다. 실제 실행 결과는 정의 파일과 분리하고 [검증 기록](../VALIDATION.md)에 그 범위를 명시합니다.

B19–B26은 포괄적 목표 선택, 작은 작업 유지, 첫 후보 실패 후 계속 수행, 빠른 완료, 예산 소진 시 미달 보고, 가설 판정 전용 목표, 불완전한 프로젝트 맥락, 진행 중인 목표의 연속성을 다룹니다. 계획의 분량이나 실행 시간이 길어졌다는 이유로 개선을 인정하지 않습니다. 선택한 병목에 실제로 기여하는 결과 기준인지, 단계와 목표의 완료를 구분하는지 확인합니다.

실제 평가에서는 사례별 독립 임시 저장소와 새 세션을 준비하고, 설정된 모델·reasoning·도구·권한·예산을 기록합니다. `execution-handoff` 사례는 별도 실행을 승인한 뒤 생성된 계획/프롬프트를 실행 모델에 전달하는 평가이며, 계획 스킬 단독 호출로 프로젝트가 실행되어야 한다는 뜻이 아닙니다.

원본과 개선본에 동일한 사례·초기 파일·권한을 사용합니다. 반환 텍스트뿐 아니라 실제 파일 차이, 도구 호출, 질문, 검증 명령, 완료 주장도 확인합니다. 먼저 요청 결과와 권한 준수를 판정하고, 이후 불필요한 질문·파일 생성·검증 반복·시간·토큰을 비교합니다. 비용 감소를 위해 필요한 검증을 생략한 결과는 개선으로 인정하지 않습니다.

평가자는 `must`와 `must_not`을 실제 실행 기록에 근거해 판정하고 증거 위치를 남깁니다. 모델 자신이 쓴 성공 선언이나 문자열 일치만으로 행동 통과를 판정하지 않습니다. 각 사례는 반복 실행해 변동성을 확인하되, 실행 횟수·환경·미수행을 모두 보고합니다. 실제 모델 결과는 배포된 시나리오 정의와 분리해 보관합니다.
