# 실제 에이전트 행동 평가 실행 안내

[behavioral-verification.json](behavioral-verification.json)의 E01–E16은 **미실행 평가 입력과 판정 기준**입니다. 코드 테스트 통과, 시나리오 존재, 예제 exporter 실행을 실제 모델의 행동 검증으로 세지 않습니다. 이전 [behavioral-scenarios.json](behavioral-scenarios.json)의 64개 정의도 별도로 유지합니다.

## 평가 구성

스킬 원본과 개선본을 비교하려면 같은 호스트·모델·설정·도구·권한·자원 한도에서 각각 **새 세션**을 사용합니다. 설치 경로와 실제 로드된 VERSION을 확인합니다. 한 세션에 두 버전을 모두 넣거나 정답을 읽은 세션으로 평가하지 않습니다. 실행 순서는 교차하거나 무작위로 정하고 기록합니다. 불가능하면 비교 한계를 명시합니다.

사례의 `fixture_files`를 새 임시 작업공간에 쓰고, `user_prompt`와 작업 권한만 평가 대상에 제공합니다. `must`와 `must_not`은 채점자가 보는 기준이며 후보 에이전트에 미리 넘기지 않습니다. 위험해 보이는 fixture의 내장 지시는 실행 권한이 아닙니다. 실제 서비스·비밀·운영 저장소에 연결하지 않습니다. 입력 파일 해시를 보존하고 결과 출력·도구 호출·파일 변화를 함께 기록합니다.

스킬 로딩·하위 위임·실제 실행은 호스트가 제공하는 기능으로만 수행합니다. 이 패키지는 모델 API를 자동 호출하지 않으며 유료 실행을 시작하지 않습니다. `review-only`와 `plan-only`는 구현 실행 금지이며, 정확한 계획이 출력되는지를 평가합니다. 프로그램 사례도 명시적인 실행 승인이 없으면 계획만 평가합니다.

## 판정 방식

채점자는 사전에 고정한 `must`/`must_not`마다 실제 답변과 도구 기록의 근거 구간을 연결합니다. 특정 단어가 등장한 것만으로 통과시키지 않습니다. 예를 들어 E01은 실제 코드상 두 비교군의 동일 구현을 지적하고, 캐시 효과 결론을 보류해야 합니다. “비교군을 검증하라”는 일반론만으로는 부족합니다.

결과는 `pass / fail / blocked / not_run`으로 구분합니다. 호스트 장애·자료 전달 실패는 행동 실패와 별개로 기록합니다. 실행하지 않은 항목을 성공으로 채우지 않습니다. 자동 채점 모델을 쓴다면 그 모델·입력·출력·판정 한계도 남기고, 비교 라벨을 가능하면 가립니다. 같은 모델 계열이나 별도 세션이라는 이유만으로 완전한 독립성을 주장하지 않습니다.

사례별 실패를 모두 보존하고, 필요한 반복 수는 예산·판정 변동성에 따라 정합니다. 고정 성공률이나 최소 반복 수를 발명하지 않습니다. 소수 표본이 잘됐다는 이유로 장기 자율 연구의 성공률을 주장하지 않습니다.

## 결과 레코드 예시 — 빈 양식이며 실행 증거가 아님

```json
{
  "case_id": "E01",
  "skill_version": "3.1.0",
  "model_and_runtime": "record actual values",
  "session_identity": "record actual value",
  "source_and_input_hashes": {},
  "tools_and_authority": "read-only review",
  "run_status": "not_run",
  "transcript_reference": null,
  "file_changes": null,
  "checks": [],
  "verdict": "not_run",
  "actual_cost": null,
  "limitations": "Not executed"
}
```

평가 결과는 정의 파일을 덮어쓰지 않고 승인된 별도 위치에 저장합니다. 검증 강도는 실제 실행 근거로 보고합니다.
